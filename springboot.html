Introducción

¿Qué es Spring Boot?

Spring Boot es un framework de Java que simplifica la creación de aplicaciones basadas en Spring Framework. Elimina la necesidad de configuraciones XML extensas y permite crear aplicaciones listas para producción con mínimo esfuerzo.

  • Auto-configuración: Detecta dependencias en el classpath y configura automáticamente los beans necesarios.
  • Servidor embebido: Incluye Tomcat, Jetty o Undertow. No necesitas un servidor externo.
  • Convención sobre configuración: Valores por defecto inteligentes que puedes sobreescribir.
  • Spring Initializr: Herramienta web para generar proyectos con las dependencias que necesites.

Arquitectura

Arquitectura por Capas en Spring Boot

Spring Boot promueve una arquitectura limpia separada en capas con responsabilidades bien definidas:

  • Controller (Presentación): Recibe peticiones HTTP y devuelve respuestas. No contiene lógica de negocio.
  • Service (Lógica de Negocio): Contiene las reglas de negocio, validaciones y orquestación.
  • Repository (Acceso a Datos): Interactúa con la base de datos usando JPA/Hibernate.
  • Entity (Modelo): Representa las tablas de la base de datos.
  • DTO (Data Transfer Object): Objetos para transferir datos entre capas sin exponer entidades.
  • Mapper: Convierte entre Entidades y DTOs.

Anotaciones Fundamentales de Spring

Las anotaciones (@) son la forma en que Spring Boot entiende qué rol cumple cada clase.

AnotaciónQué haceDónde se usa

@ServiceVariante de @Component. Indica que la clase contiene lógica de negocioCapa Service
@RepositoryVariante de @Component. Indica acceso a datos y traduce excepciones SQLCapa Repository

Anotaciones Web

Anotaciones para REST APIs

AnotaciónQué hace
@RestControllerCombina @Controller + @ResponseBody. Cada método retorna JSON directamente.
@RequestMappingDefine la ruta base del controlador (ej: "/api/chefs").
@GetMappingMapea peticiones HTTP GET a un método.
@PostMappingMapea peticiones HTTP POST a un método.
@PutMappingMapea peticiones HTTP PUT a un método.
@DeleteMappingMapea peticiones HTTP DELETE a un método.
@PathVariableExtrae valores de la URL (ej: /chefs/{id}).
@RequestBodyConvierte el cuerpo JSON de la petición a un objeto Java.
@RestController @RequestMapping("/api/chefs") public class ChefController { private final ChefService chefService; @PostMapping public ResponseEntity<ChefResponse> crearChef(@RequestBody ChefRequest req) { return ResponseEntity .status(HttpStatus.CREATED) .body(chefService.crearChef(req)); } @GetMapping("/{id}") public ResponseEntity<ChefResponse> obtenerPorId(@PathVariable UUID id) { return ResponseEntity .ok(chefService.obtenerPorId(id)); } }
Anotaciones JPA

Anotaciones de Persistencia (JPA / Hibernate)

AnotaciónQué hace
@EntityMarca la clase como tabla en la base de datos.
@TableDefine el nombre de la tabla (ej: @Table(name = "chefs")).
@IdDefine el campo como clave primaria.
@GeneratedValueGenera el valor automáticamente (AUTO, UUID, IDENTITY, SEQUENCE).
@ColumnPersonaliza la columna (nombre, nullable, unique, length).
@OneToManyUn registro tiene muchos hijos (Chef → Platos).
@ManyToOneMuchos registros pertenecen a uno (Plato → Chef).
@ManyToManyRelación N:M con tabla intermedia (Cliente ↔ Plato).
@JoinColumnColumna FK en relaciones @ManyToOne.
@JoinTableTabla intermedia en relaciones @ManyToMany.
@Entity @Table(name = "dishes") public class Dish { @Id @GeneratedValue(strategy = UUID) private UUID id; private String nombre; private BigDecimal precio; @ManyToOne(fetch = LAZY) @JoinColumn(name = "chef_id") private Chef chef; @ManyToMany(mappedBy = "platosConsumidos") private List<Client> clientes; }
Relaciones JPA

Tipos de Relaciones en JPA

@OneToMany / @ManyToOne

Ejemplo: Un Chef tiene muchos Platos. Un Plato pertenece a un Chef.

Chef (1) ──→ (N) Dish Tabla: dishes chef_id FK → chefs.id

@ManyToMany

Ejemplo: Un Cliente consume muchos Platos. Un Plato es consumido por muchos Clientes.

Client (N) ←→ (N) Dish Tabla intermedia: dish_clients client_id FK → clients.id dish_id FK → dishes.id

@OneToOne

Ejemplo: Un Usuario tiene un único Perfil. Se usa @JoinColumn en el lado dueño.

User (1) ←→ (1) Profile Tabla: profiles user_id FK → users.id
Lombok

Anotaciones de Lombok

Lombok genera código repetitivo (boilerplate) en tiempo de compilación, reduciendo líneas drásticamente.

AnotaciónQué genera
@GetterTodos los métodos get (ej: getNombre())
@SetterTodos los métodos set (ej: setNombre())
@NoArgsConstructorConstructor vacío (requerido por JPA)
@AllArgsConstructorConstructor con todos los campos
@BuilderPatrón Builder para crear objetos de forma fluida
@RequiredArgsConstructorConstructor solo con campos final (inyección de dependencias)
@DataCombina @Getter + @Setter + @ToString + @EqualsAndHashCode
// SIN Lombok: ~60 líneas public class Chef { private UUID id; private String nombre; public UUID getId() { return id; } public void setId(UUID id) { ... } public String getNombre() { ... } public void setNombre(String n) { ... } public Chef() {} public Chef(UUID id, String n) { ... } // toString, equals, hashCode... } // CON Lombok: ~8 líneas @Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder public class Chef { private UUID id; private String nombre; }

Spring Data JPA

Repositorios y Consultas Personalizadas

Spring Data JPA genera automáticamente consultas SQL por el nombre del método o mediante JPQL.

  • Query Methods: Spring interpreta el nombre del método y genera SQL automáticamente.
  • @Query (JPQL): Consultas en lenguaje JPQL usando nombres de entidades Java.
  • @Query (nativeQuery): SQL nativo directamente contra la base de datos.

Ejemplo de Query Methods generados automáticamente:

findByNombre(String nombre) → SELECT * FROM chefs WHERE nombre = ? findByEmailContaining(String email) → SELECT * FROM clients WHERE email LIKE '%?%'
public interface ClientRepository extends JpaRepository<Client, UUID> { // 1. Query Method (automático) Optional<Client> findByEmail(String email); // 2. JPQL con JOIN @Query(""" SELECT d.chef FROM Client c JOIN c.platosConsumidos d GROUP BY d.chef ORDER BY COUNT(d) DESC LIMIT 1 """) Optional<Chef> findChefConMasVentas(); // 3. JPQL con parámetros @Query(""" SELECT d FROM Client c JOIN c.platosConsumidos d WHERE c.id = :clientId AND d.chef.id = :chefId """) List<Dish> findPlatosDeClientePorChef( @Param("clientId") UUID clientId, @Param("chefId") UUID chefId); }
Concepto Clave

Inyección de Dependencias (IoC)

Inversión de Control (IoC) es el principio fundamental de Spring. En lugar de que tú crees los objetos con new, Spring los crea y los inyecta automáticamente.

  • ¿Qué es un Bean? Un objeto gestionado por Spring (marcado con @Component, @Service, @Repository, etc.).
  • ¿Cómo se inyecta? Por constructor (recomendado), por campo (@Autowired) o por setter.
  • ¿Por qué por constructor? Inmutabilidad, testabilidad y claridad de dependencias.
// ❌ SIN Inyección de Dependencias public class ChefController { private ChefService service = new ChefService(new ChefRepository()); // Acoplamiento fuerte, difícil de testear } // ✅ CON Inyección de Dependencias @RestController @RequiredArgsConstructor public class ChefController { // Spring inyecta el service automáticamente private final ChefService chefService; // Fácil de testear con mocks }
Organización

Estructura de un Proyecto Spring Boot

src/ ├── main/ │ ├── java/com/example/app/ │ │ ├── AppApplication.java ← @SpringBootApplication │ │ ├── chef/ │ │ │ ├── controller/ │ │ │ │ └── ChefController.java ← @RestController │ │ │ ├── service/ │ │ │ │ └── ChefService.java ← @Service │ │ │ ├── repository/ │ │ │ │ └── ChefRepository.java ← @Repository │ │ │ ├── entity/ │ │ │ │ └── Chef.java ← @Entity │ │ │ ├── dto/ │ │ │ │ ├── ChefRequest.java ← record │ │ │ │ └── ChefResponse.java ← record │ │ │ └── mapper/ │ │ │ └── ChefMapper.java ← static │ │ └── common/ │ │ └── exception/ │ │ └── GlobalExceptionHandler.java │ └── resources/ │ └── application.yml ← Configuración ├── test/ │ └── java/com/example/app/ │ ├── chef/ │ │ ├── service/ChefServiceTest.java │ │ ├── mapper/ChefMapperTest.java │ │ └── controller/ChefControllerTest.java │ ├── integration/ChefIntegrationTest.java │ └── e2e/ChefE2ETest.java

Convenciones

  • Paquetes por feature (chef/, dish/, client/) no por capa.
  • DTOs como Records: Desde Java 14, los records son ideales para DTOs inmutables.
  • application.yml: Configuración en formato YAML con perfiles (dev, test, prod).
  • Pruebas separadas: Unitarias en paquete del módulo, integración y E2E en paquetes propios.

Archivos clave

  • build.gradle / pom.xml: Dependencias y plugins del proyecto.
  • application.yml: Puerto, BD, JPA, logging.
  • application-test.yml: Perfil de test con H2 en memoria.
  • compose.yml: Docker Compose para PostgreSQL.
